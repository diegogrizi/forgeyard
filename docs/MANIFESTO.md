# Manifesto for an Agentic Harness Factory

I describe the software. The factory prepares the system that will build it.

I want to develop software, not become an expert in the ecosystem of tools that are supposed to help me develop it.

Today I may work on a microservice, tomorrow on a frontend, and the next day on a completely different application. I cannot know every language, framework, specialist practice, coding agent, skill repository, planning method, command, and orchestration system. If using AI first requires me to assemble and direct an AI team, a substantial part of the problem is still mine.

Forgeyard exists to absorb that complexity. It accepts a description, specification, documents, or an existing repository; understands the work; prepares an appropriate agentic environment; explains its decisions; and supports delivery through verifiable evidence.

## 1. Remove the burden of ecosystem choice

The problem is not a shortage of skills. The problem is having to discover, assess, compare, install, reconcile, and remember them.

Aggregation must produce a useful decision rather than another list to study. The factory knows the supported alternatives, selects a coherent minimum for the project, and records why it selected or excluded each material component. Advanced users may override the result, but ordinary use must not require ecosystem expertise.

## 2. Build the working environment, not only code

A harness is the operational structure through which agents work: instructions, capabilities, tools, context, roles, procedures, controls, evidence, and coordination rules.

The factory creates this structure from the software objective. It may use supported third-party agents and tools; it does not need to invent a model or editor. Its product is a coherent, project-scoped development environment, not a pile of prompts.

## 3. Enter through the problem

The normal input is a software objective plus any repository, specification, documents, constraints, available tools, and desired autonomy.

Forgeyard reads what already exists before asking questions. It detects stack, structure, conventions, and quality commands when evidence supports them. Questions concern the product, material constraints, or genuine ambiguities—not internal skill authors, orchestration brands, or catalog trivia.

## 4. Maintain a curated foundation

The factory maintains a pinned, licensed, attributable, and reviewed knowledge base. It does not install every novelty or treat popularity as quality.

Updates to that foundation are explicit and verified. Project preparation uses only the relevant subset. When a capability is missing, Forgeyard distinguishes verified evidence from inference and uncertainty.

## 5. Composition includes exclusion

Forgeyard chooses one primary delivery method, adds only the capabilities required by the project, and prevents duplicate or conflicting authorities.

Roles have clear responsibilities. Hooks and gates have explicit timing and failure behavior. Requirements, state, decisions, evidence, and delivery reports each have one authoritative location. Five coherent components are better than two hundred accumulated components.

## 6. Ordinary use does not require skill or command knowledge

After preparation, the user speaks in the language of the project: implement a feature, fix a defect without changing the public contract, or resume previous work.

The host controller selects the procedure, context, roles, and checks. Commands and skills remain inspectable advanced interfaces; memorizing or sequencing them is not an ordinary-use requirement.

## 7. Connect specification to verified delivery

The generated environment connects clarification, requirements, planning, tasks, implementation, tests, review, and delivery. Tasks derive from requirements; implementation answers tasks; verification checks acceptance behavior.

State, decisions, checkpoints, and evidence persist in the repository. Completion claims identify the exact task, command, and Git revision that support them.

## 8. Make autonomy proportional and governable

Users may provide tools, time, budget, intensity, supervision, and concurrency constraints without having to configure internal orchestration.

The factory translates those constraints into a reasonable operating policy. It does not multiply agents for appearance. It stops on material ambiguity, exhausted limits, repeated failure, unsafe scope, or actions requiring authorization.

## 9. Let the factory evolve while project suites remain stable

The factory may evolve its curated base. A generated project suite remains identifiable and pinned. Factory updates never silently mutate an existing project.

Project requirements and knowledge continue to evolve, but harness upgrades are explicit, previewable, reversible, and motivated by a real need.

## 10. Be multipurpose by tailoring each project

Forgeyard supports different project classes and both new and existing software. Generality must produce different, evidence-based configurations—not one generic environment copied everywhere.

Supported agentic hosts are replaceable behind declared capability boundaries. Differences are adapted where safe and disclosed where not.

## 11. Hide operational complexity, not accountability

Ordinary use is simple. Every consequential factory decision remains inspectable: observed facts, confidence, selected and excluded components, versions, permissions, limits, and uncertainties.

Forgeyard never presents an inference as verified evidence or structural validation as a successful real-client run.

## Success criterion

Forgeyard succeeds when the user can move from:

> I must discover tools, select skills, configure agents, and learn how to coordinate them.

to:

> This is the project. This is the outcome. These are the constraints. Prepare the appropriate environment and support the work until the result is verified.

Its value is measured by avoided operational decisions, reduced manual coordination, and verifiable delivery quality—not by the number of installed skills, agent definitions, or generated files.
